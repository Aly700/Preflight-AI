# Week 1 generated data dictionary

Generated by `scripts/generate_synthetic.py` version `1.0.0`, using
`config/synthetic_spec.json` and seed `20261102`. All records, names, descriptions,
assignments and histories are original fiction created by the generator. Its
only source input is the supplied configuration; no operational records or
external sources were accessed or transformed.

## Format and relationships

The seven CSVs in `data/synthetic/` use UTF-8 without a BOM, LF line endings,
one header row, and ascending primary-key order. Fields are strings; optional
values are empty cells. All timestamps use ISO 8601 UTC with `+00:00`.
IDs have the configured fictional prefix and a zero-padded numeric suffix.
Event IDs are assigned after chronological sorting, with deterministic ties.

| File (rows) | Columns and meaning |
|---|---|
| `aircraft.csv` (12) | `aircraft_id`: primary key, `DEMO-AIR-`; `program`, `stage`, `station`: configured fictional grouping labels; `record_created_at`: record creation time. |
| `issues.csv` (180) | `issue_id`: primary key, `ISSUE-`; `aircraft_id`: aircraft foreign key; `title`, `description`: generic fictional record questions; `subsystem`, `priority`: configured filter categories; `status`: current issue state; `opened_at`: initial opening time; `closed_at`: current closure time, otherwise blank. |
| `tasks.csv` (480) | `task_id`: primary key, `TASK-`; `issue_id`: issue foreign key; `task_kind`: configured category; `status`: current task state; `assigned_team_id`: team foreign key; `assigned_person_id`: optional person foreign key, belonging to that team; `created_at`: task creation time; `completed_at`: completion time only for currently completed tasks. |
| `activity_events.csv` (920) | `event_id`: primary key, `EVT-`; `issue_id`: issue foreign key; `task_id`: optional foreign key to a task on that issue; `actor_id`: optional person foreign key; `event_type`: configured event category; `occurred_at`: event time; `note`: generic fictional context. |
| `teams.csv` (6) | `team_id`: primary key, `TEAM-`; `team_name`: invented label such as `Demo Team 01`. |
| `people.csv` (36) | `person_id`: primary key, `PERSON-`; `display_name`: fictional label such as `Demo Worker 0001`; `team_id`: team foreign key. |
| `shifts.csv` (150) | `shift_id`: primary key, `SHIFT-`; `person_id`: person foreign key; `team_id`: that person's team; `shift_start_at`, `shift_end_at`: start and end of an eight-hour assignment. |

Aircraft have issues; issues have tasks and events. Teams have people, tasks
and shifts. Events with tasks always refer to the same issue as those tasks.
An empty event actor represents an unattributed fictional record event; an
empty task assignment means team-only ownership (72 tasks in this generation).

## States and coverage

| Current issue status | Rows | Current task status | Rows |
|---|---:|---|---:|
| `open` | 72 | `todo` | 309 |
| `in_progress` | 54 | `in_progress` | 54 |
| `blocked` | 18 | `blocked` | 18 |
| `reopened` | 18 | `awaiting_review` | 18 |
| `closed` | 18 | `completed` | 81 |

All three priorities, six subsystems, five task kinds and eleven event types
are represented. Every issue has two or three tasks and multiple events.
Eighteen open issues have a completed task; completing a task does not close
its issue. Closed issues have all tasks completed before closure. Reopened
issues have a completed earlier task, an earlier closure, a later reopening,
and new pending tasks after reopening; their current `closed_at` is blank.
Every blocked issue has a blocked task. Review requests remain incomplete.

## Reproduction and manifest

```bash
python3 -B scripts/generate_synthetic.py --config config/synthetic_spec.json --seed 20261102 --output data/synthetic
python3 -B -m unittest discover -s tests -p test_synthetic_contract.py -v
```

`--seed` overrides the config seed (including zero); omitting it uses the
config seed. `--config` and `--output` accept alternate paths. The same config
and seed reproduce CSV bytes in the verified Python 3.14.8 environment.
`manifest.json` contains `phase`, effective `seed`, `config_sha256` (exact input
file bytes), `generator_version`, `generated_at_utc`, actual per-table `counts`,
and `files` entries with each CSV's `rows` and `sha256`. Only the generation
timestamp is expected to vary between otherwise identical runs.

## Known limitations

- This is demonstration data, not an estimate of operational rates, staffing,
  workload or maintenance practice. Labels such as `inspection` and
  `rectification` are categories only, without procedures or sign-offs.
- Repeated workload profiles and balanced categories deliberately provide query
  coverage. Individual timestamps, allocations and row ordering use a local
  seeded random generator. Cross-version Python reproducibility is untested.
- The fictional history window is January 1–October 31, 2026. Aircraft records
  start at its beginning; issue openings reserve fourteen days for subsequent
  histories. These dates describe fictional history, not a seven-day dataset.
- Events include every issue opening, task creation and current task transition,
  plus closure/reopening histories and selected assignments/context. They are
  a compact history, not a complete audit of every intermediate transition.
- Shifts are sampled assignments, do not overlap for an individual, and do not
  cover every task or event. Eight-hour shifts may end after the history window.
- The generator supports these Week 1 enums and lifecycle profiles. Impossible
  counts or short history windows are rejected before writing datasets. Running
  into an existing output directory replaces the eight generated data files.
- This generated data package contains no NCR documents or embeddings. Application
  code is separate; see the repository README and `docs/SETUP.md` for its status.
